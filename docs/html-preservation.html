HTML 保持の仕組み

多くのエディタは HTML を内部モデルに変換するため、モデルで表せないタグや属性が消えます。formulit は DOM をそのまま編集し、さらに「原文のどこがどのノードになったか」を覚えておくことで、編集していない部分を元の文字列のまま返します。

比べてみる

左に HTML を書いて「読み込む」を押し、エディタで一部を編集してください。formulit の value と、比較用の ブラウザ標準の書き出し（innerHTML 相当）を並べて表示します。原文と違う行は色が付きます。

保証されること


    
  
  1. 未編集なら原文そのまま — value を設定して何も編集していなければ、1 文字も変えずに同じ文字列を返します（引用符・大文字・空白・<br/>・&copy; の書き方まで）。ソース表示で編集した HTML も同様です。
    2. 
  
  2. 編集後も未変更部分は原文そのまま — 読み込み時に原文とノードを対応づけ、変更を追跡します。
    
    
      
    ノードの状態書き出し方
    
      
    変更なし原文の文字列そのまま（省略された終了タグも元のまま）
    
      
    中身だけ変更原文の開始タグ・終了タグ + 中身を同じ規則で処理
    
      
    属性を変更・新しく追加ブラウザのシリアライズ
    
    
    
  
    3. 
  
  3. 出力は常に編集結果と一致 — つなぎ目で意味が変わるおそれがあるとき（終了タグを省略した <p>x の直後に別の内容が来た等）は、組み立てた HTML を再パースして DOM と等価か確かめ、等価でなければ文書全体をブラウザの書き出しで返します。
    4. 
  
  4. DOM にあるものは消さない — class・style・data-*・独自要素・空要素・コメント・details・iframe・<style> など。エディタが編集用に付けた属性（contenteditable 等）は、出力時に元の値と並び順に戻ります。
    5. 




出力が変わるケース



  
ケース理由

  
初期値を <template> や value 属性で渡すと、書き方が整形されるブラウザが先にパースするため。原文そのままにするなら value プロパティか <script type="text/html">

  
<script>・on* 属性・javascript: URL が消える既定の sanitize="strip"。残すなら sanitize="none"（信頼できる利用者向け）

  
除去が起きた文書は、未編集でも dirty が true危険な記述を「原文そのまま」で素通しさせないため

  
不正な入れ子（<p> の中の <div> など）が直るブラウザのパーサーが読み込み時に直すため

  
属性を変えた要素は " 囲みなどブラウザの書き方になるその要素だけ作り直すため

  
末尾に画像・表などを挿入すると後ろに <p><br></p> が入る続けて入力できるようにするため

  
他のページからコピーした要素の style が消える（Chrome / Safari）コピー時にブラウザが書き込む計算済みスタイルを除去するため。手書き HTML はソース表示に貼り付ける

  
アップロード中の画像の src が blob:完了後に本来の URL へ差し替わる





編集させたくない要素


protect 属性の CSS セレクタに一致する要素は、編集中 contenteditable=false になり、丸ごと選択・削除だけができます（出力には付きません）。既定は iframe・video・form・svg・メディア埋め込み・[data-protect] など。読み込み直した後も保護したい HTML には data-protect を付けてください。



性能


約 200KB・2 万ノードの文書で、読み込み時の対応づけに約 0.1 秒。入力中のエディタ側の処理は約 300 段落の文書で 1 文字あたり約 1ms です。連続入力中はツールバーの表示更新をまとめて行い、書き出しはつなぎ目に不安がない限り再パースを省きます。
